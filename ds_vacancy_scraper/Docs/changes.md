# Документация по изменениям (DS Vacancy Scraper)

## Изменения v2 (Новые API и параметры):
1. **Смена источников (Открытые API)**:
   - Полностью убраны **HH.ru** и **Работа России**. 
   - Добавлены новые источники, доступные без приватных токенов:
     - **Habr Career API** (скрытое Frontend JSON API) — отличный ресурс для русского IT.

     - **Remotive API** — глобальное открытое REST API (`remotive.com/api`), отлично подходит для поиска удаленных IT-вакансий (в т.ч. DS).

   - `requirements` — ключевые навыки и требования (Python, SQL, Scikit-learn, ML и т.д.).
3. **Обновление структуры**:
   - Таблица теперь сохраняется в файл **`ds_junior_advanced.csv`** с расширенным набором колонок: `[source, title, company, city, work_format, requirements, salary, link]`.

## Подготовка данных для машинного обучения (Очистка и EDA)

1. **Профессиональная обработка колонки зарплат:**
   - Ранее колонка salary содержала смешанные типы данных (числа, строки с «от» и «до», валюты). Для профессионального анализа это недопустимо.
   - Создан новый числовой признак salary_num, который корректно парсит числа из строк. Если указана «вилка» (от и до) — берется среднее значение.
   - **Целевой признак для обучения (Target):** salary_num. Эта колонка идеально подходит для задачи регрессии (предсказание уровня зарплаты).

2. **Feature Engineering (Генерация новых признаков):**
   - 
eq_len — количество требований (навыков), извлеченных из колонки 
equirements.
   - is_remote — бинарный признак (1 — удаленная работа, 0 — офис/гибрид).
   - source_code — закодированный источник вакансии (категориальный признак).

3. **Разведочный анализ данных (EDA):**
   - Построена гистограмма распределения зарплат (plots/salary_dist.png).
   - Построена матрица корреляций между новыми численными признаками (plots/correlation_matrix.png), что поможет выбрать признаки для обучения модели.
   - Очищенный датафрейм сохранён как data/ds_vacancies_analysis_cleaned.csv.


## Обучение первой ML модели (Регрессия)

1. **Создан скрипт 	rain_model.py:**
   - Выделен целевой признак (salary_num) и фичи (
eq_len, is_remote).
   - Набор данных разделен на тренировочную (80%) и тестовую (20%) выборки.
   - Обучены две модели: **Linear Regression** и **Random Forest Regressor**.
   
2. **Результаты и образовательный момент:**
   - Модели показали очень низкий/отрицательный ^2$ (около -0.08). Это абсолютно нормально для текущего набора данных! 
   - Поскольку зарплаты генерировались с помощью 
p.random (синтетически) в process_vacancies.py, алгоритм математически подтвердил отсутствие реальной связи между навыками и случайной зарплатой. (Хороший пример принципа Garbage In -> Garbage Out).
   - Линейная регрессия показала, что вес 
eq_len составляет ~2659 рублей, что говорит о слабом случайном шуме.
   
3. **Обновлена теория:**
   - Добавлен файл 	heory/ml_basics.md с подробным описанием разницы между регрессией и классификацией, а также объяснением метрик MAE, MSE, R^2.


## Обучение второй ML модели (Классификация)

1. **Создан скрипт 	rain_classification.py:**
   - Произведен переход от задачи Регрессии к задаче Классификации.
   - Числовая зарплата (salary_num) разбита на 3 категории (класса): Low (< 150к), Medium (150к - 220к) и High (> 220к).
   - Обучена модель **Random Forest Classifier**.
   
2. **Результаты Классификации:**
   - Выведен Classification Report (отчет по классификации), включающий метрики: Accuracy, Precision, Recall, F1-score.
   - Так как данные синтетические (и распределены случайно), Accuracy составила около 28-33% (что математически эквивалентно случайному угадыванию из 3 классов, /3 pprox 33\%$). Это вновь отлично подтверждает теорию для защиты проекта!
   - Создан график plots/req_len_vs_salary_class.png (Boxplot + Stripplot), визуализирующий распределение количества навыков внутри каждого класса зарплат.
   
3. **Обновлена документация:**
   - Создан файл docs/conclusion.md с итоговым обзором проделанной работы, подчеркивающим все навыки, которые получил автор (Захар) в ходе реализации проекта.

## Рефакторинг и Новые источники данных (Сбор реальных зарплат)

1. **Организация структуры проекта (Best Practices):**
   - Проект был реструктурирован согласно стандартам Data Science (MLOps).
   - Созданы директории:

     - src/data_processing/ — для скриптов очистки, EDA и генерации таблиц.
     - src/models/ — для скриптов машинного обучения.
     - data/raw/ и data/processed/ — для разделения сырых и очищенных данных.

2. **Новые источники данных (Scrapers):**
   - Разработан src/data_collection/scraper_hh.py для сбора данных через публичный API HeadHunter.
   - Разработан src/data_collection/scraper_remotive.py для парсинга международных Data Science вакансий (Remotive API).

equirements) и парсинг РЕАЛЬНЫХ зарплат (salary_num) напрямую из JSON-ответов. Ненужные фичи (Название, город, сорс) были исключены еще на этапе сбора данных, что экономит память.
