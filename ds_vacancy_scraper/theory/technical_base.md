# Техническая база проекта (Data Science Vacancy Scraper)

В этом документе описана техническая сторона проекта: как устроены основные скрипты, за что отвечает каждая функция и как данные проходят путь от сырого API до готового для машинного обучения датасета.

---

## 1. Сбор данных: `scraper.py`
Этот скрипт отвечает за извлечение данных (парсинг) о вакансиях с платформы Habr Career через их скрытое API.

### Основные компоненты:
- **`HEADERS`** — это HTTP-заголовки. Они нужны, чтобы сервер думал, что запросы делает настоящий браузер (Chrome), а не автоматический скрипт. Это помогает избежать блокировок.

- **`parse_habr_api(query, qualifications)`** — главная функция парсинга.
  - **Как работает:** Делает GET-запросы к `https://career.habr.com/api/frontend/vacancies`.
  - **Пагинация (переход по страницам):** В цикле перебирает страницы (`page = 1, 2...`) до тех пор, пока API не вернёт пустой список.
  - **Парсинг JSON:** Извлекает данные в формате JSON и аккуратно достаёт оттуда нужные поля: название (`title`), компанию (`company`), город (`city`), формат работы (офис или удалёнка), навыки (`skills` -> переходит в `requirements`) и зарплату (`salary`).
  - **Обработка ошибок:** Блок `try-except` страхует код от падений, если вдруг пропадёт интернет или сервер вернёт ошибку.

- **`main()`** (в `scraper.py`)
  - Задаёт параметры поиска (запрос `"Data Science"` и уровни грейдов: от стажера до сеньора).
  - Убирает дубликаты (сверяет по уникальной ссылке на вакансию).
  - Сохраняет результат в файл `data/ds_vacancies_updated.csv` при помощи встроенной библиотеки `csv`.

## 2. Обработка данных: `process_vacancies.py`
Этот скрипт берёт "сырые" собранные данные и выполняет их предварительную очистку и аугментацию (обогащение). Здесь используется библиотека `pandas` — золотой стандарт в Data Science.

### Основные компоненты:
- **`load_vacancies(file_path)`** — базовая функция загрузки. Проверяет существование файла и читает его в структуру DataFrame (таблицу).
- **`add_mock_salaries(df, seed, fill_all)`** — функция для образовательных целей.
  - Так как в реальных вакансиях зарплата часто скрыта, эта функция "придумывает" правдоподобные зарплаты (от 80 000 до 320 000 руб.) с помощью `numpy.random`.
  - `seed=42` гарантирует воспроизводимость: при каждом запуске генератор случайных чисел выдаст одни и те же значения, что критично для отладки.
- **`main()`** (в `process_vacancies.py`)
  - Выстраивает Pipeline (конвейер) данных: Загрузка -> Заполнение пропусков зарплат -> Вывод статистики (`df.info()`, `df.describe()`) -> Сохранение в `data/ds_vacancies_processed.csv`.

## 3. Подготовка к Machine Learning (Выбор целевой переменной)
Сырые текстовые строки (вроде "от 50 000 до 100 000 ₽") не подходят для машинного обучения. Алгоритмы "понимают" только числа.

**Профессиональные стандарты, применённые к нашему финальному набору:**
1. **Таргет (Целевая переменная):** `salary_num`. Мы извлекли численные значения из строк с зарплатами. Если указана "вилка", берётся её математическое среднее. Это наша **целевая переменная** — то, что мы будем предсказывать. Решается задача **регрессии** (предсказание непрерывной величины).
2. **Feature Engineering:**
   - Категориальные строковые признаки вроде `work_format` переведены в бинарные (числовые) флаги `is_remote` (1 или 0).
   - Из текстовых требований `requirements` извлечён новый признак `req_len` (число требуемых навыков), так как алгоритм не сможет напрямую читать текст без NLP (обработки естественного языка).

Эти численные преобразования позволяют нам строить матрицы корреляции и скармливать данные таким алгоритмам, как линейная регрессия или случайный лес.
